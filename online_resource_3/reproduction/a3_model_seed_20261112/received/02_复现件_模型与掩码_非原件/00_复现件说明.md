## 为什么这次再执行是等价的

| 环节 | 依据 |
|---|---|
| 划分 | `dev_split(y, seed=s, stratify=True)`，s ∈ {11,22,33,44,55}，42000/9000/9000；与归档 `aps_seed*.npz` 的 `train_rows`/`val_rows` 逐位相同（已核） |

| 评价 | `build_eval_inputs(Xva)["S1_30_101"][0]`，average precision |
| 结果 | 30 格 AP 与 `01_当次执行记录_原件/results_seed/` 的记录 **30/30 逐位相等，偏差 0.0** |

## 怎么用

```python
import joblib, numpy as np
m = joblib.load("A3_repro_2026-11-12/model_s11_C_2026.joblib")   # 只加载本包内文件
z = np.load("A3_repro_2026-11-12/preds_s11.npz")
shape = tuple(int(x) for x in z["delmask_shape"])
bits = np.unpackbits(z["delmask_C"])[: shape[0] * shape[1]].reshape(shape).astype(bool)
print(bits.sum(), z["mask_sha256"])     # 新增遮蔽单元数与哈希，对照 03 的表格
```

`model_*.joblib` 与 `.npz` 都是本地可信文件；`joblib.load` 会反序列化执行代码，不要对来源不明的同名文件用。

## 边界

1. AP 逐位相等是概率向量一致的强证据，不是数学证明；严格表述是「同配置再执行下，指标与历史记录完全一致」。
2. 当次运行的库版本没有回执；本目录 `environment.json` 是复现运行的环境，只对它自己成立。
3. 本目录没有重训之外的任何改动：不动冻结协议、不动 `results_seed/` 历史记录、不动任何投稿包文件。
